# Принятые решения

## MEAL-10

1. **Feature-first + стандартный Flutter.** Реальная логика в контроллере,
   HTTP и SQLite отдельно; нет пустых repository/use-case слоёв.
2. **Не пересчитывать серверный результат.** Ввод денег — десятичные строки
   (backend принимает Decimal-строки); валидация границ через BigInt и текст,
   вывод уже округлённых сервером денег — форматирование, не float-арифметика.
   Дневные итоги не суммируются из округлённых приёмов.
3. **Fail-closed хранение токена.** Single-flight установки, контрольная запись/
   чтение secure storage; при ошибке генерация не продолжается. 401 не повод
   создавать новую установку. Сброс отдельный и подтверждаемый.
   После P1: явно `AndroidOptions(resetOnError: false)`, в том числе override
   параметров операций внедрённого storage. Default true в плагине 10.3.4
   удаляет повреждённую запись и маскирует ошибку как отсутствие токена.
4. **Идемпотентность ограничена временем.** Ключ — 192 случайных бита,
   48 hex ASCII-символов. Снимок/ключ/дата/deadline сохраняются до POST.
   В API нет TTL discovery, поэтому без подтверждённого оператором
   `API_MIN_RETENTION_SECONDS` recovery POST блокируется. Это клиентский public
   deployment setting, не придуманное поле backend. Запас — 60 секунд; автоматических
   POST retries нет вообще. Смена retention/часов требует осторожности и оператора.
5. **Привязка к серверу и владельцу.** URL включает base path; разные URL не
   разделяют credentials/операции. Смена URL не удаляет старые записи. Локальные
   меню не требуют credentials и видны независимо от текущего сервера.
6. **Offline — собственный снимок.** Необходимые названия уже есть в серверном
   shopping_list, отдельный GET каталога не нужен. Metadata модели не сохраняется
   в локальном меню и не отображается в основном UI.
7. **HTTP только debug.** Dart разрешает локальные адреса, platform-конфигурация
   HTTP ограничена Debug. Release/profile требуют HTTPS; TLS bypass отсутствует.
8. **Не расширять backend ради теста.** Отдельный мобильный launcher читает его
   код и переиспользует существующий фиксированный локальный провайдер. Адаптер
   повторяет demo-день на 3/7 дней, не изменяет контракт/ядро и не зовёт DeepSeek.
   БД — новая временная, `.env` не читается.
9. **Предел обещаний.** Достоверность demo, цена магазина, безопасность еды,
   медицинская полноценность, реальное время готовки и поведение OS backup
   не доказываются успешной серверной валидацией.
10. **Один lifecycle-владелец (P2).** Владение контроллером передаётся корневому
    HomeScreen, не распределяется между main, UI и тестом. Экран освобождает
    контроллер при удалении/замене инъекции; rebuild и навигация не освобождают.
    Async-continuations проверяют dispose до новых запросов/сохранения меню.
    Уже начатую транзакцию не выдаём за отменённую.
11. **Fixtures проверяются совместно.** 3 дня × половина двухпорционного рецепта,
    бюджет 200,50, дневные цели 185/6,5/3,5/31. Серверный validate_plan подтверждает
    все ограничения, точный calculation сравнивается с fixture; отдельной
    Pydantic-валидации двух независимых JSON недостаточно.
12. **P2: регистрации координируются между экземплярами сервиса.** Общая ревизия
    и FIFO storage-секция на namespace/backend, а не отдельный счётчик экземпляра.
    HTTP вне секции; актуальность проверяется до write и после await. При отмене
    начатая запись и очистка собственного неопубликованного токена завершаются до
    допуска нового владельца; старые cleanup не удаляют новые credentials.
    Reset инвалидирует попытки сразу, delete и очистка SQLite проходят в одной
    очереди. Кэш credentials экземпляра удалён. Storage-error блокирует всю пару
    до успешного явного reset, не маскируется как отсутствие токена (P1 сохранён).
    Connection-epoch отделяет прежний create от следующего после reset.
    Гарантия ограничена одним isolate и корректным завершением Future storage;
    OS-crash до завершения reset и изменения в обход coordinator не покрываются.
