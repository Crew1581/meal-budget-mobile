## Реализовано

- Flutter/Dart, Android/iOS, Material 3 и русский интерфейс. UI, состояние сценария,
  package:http и локальные хранилища разделены по функциям приложения.
- Сохраняемая анкета на 3/7 дней: бюджет периода, собственные дневные КБЖУ,
  количество приёмов, максимум заявленного времени, регион и пожелания.
  Валидация по backend, дробная запятая и Decimal-строки для запроса. Денежной
  арифметики через binary float и расчёта медицинских целей нет.
- Lazy single-flight установки, installation_id и Bearer в flutter_secure_storage.
  Запись проверяется чтением; storage-error блокирует генерацию, 401 не создаёт
  новую установку. Android `resetOnError: false`, закреплённая версия — 10.3.4.
- Токен и операции привязаны к нормализованному адресу backend. Общий coordinator
  namespace/backend между сервисами ограждает регистрацию, запись и reset от
  устаревших ответов. Подтверждаемый сброс не удаляет сохранённые меню.
- До POST SQLite sqflite v1 атомарно сохраняет неизменяемые снимок/ключ/время/состояние.
  Double tap не создаёт параллельные отправки, редактирование не меняет снимок.
  После 202 job_id сохраняется до ожидания. При сбое его записи полученный ID
  остаётся в памяти для отдельного сохранения/GET, не нового POST.
- Перезапуск с job_id продолжает GET; неизвестный исход POST требует явного
  восстановления с прежним ключом и снимком. Автоматических POST retries нет.
  Без подтверждённого оператором `API_MIN_RETENTION_SECONDS` или после deadline
  повтор заблокирован; default TTL backend не считается гарантией.
- Lifecycle-aware polling queued/running/completed/failed: один GET, пауза,
  ограниченный backoff и Retry-After, без выдуманного процента. Background/dispose
  останавливают polling и передают abort запросам; resume возобновляет ожидание.
  Обрабатываются реальные 401/404/409/413/422/429/503; worker_unavailable не означает
  failed, ошибка GET не запускает POST. После failed новая операция только явная.
- Просмотр дней и приёмов, серверных КБЖУ, рецептов/ингредиентов/шагов, заявленного
  времени, стоимости, бюджета, упаковок и остатков. Выход полного рецепта отделён
  от порций конкретного приёма; стоимость и КБЖУ клиент не пересчитывает.
- Completed и локальное меню сохраняются транзакционно. Названия продуктов входят
  в снимок shopping_list, текущий каталог для offline-просмотра не нужен.

- API_BASE_URL через dart-define без секретов, локальный HTTP только debug,
  release/profile требуют HTTPS; проверка сертификатов не отключается.
- Контекст в AGENTS/README и docs, lock-файл, GitHub Actions format/analyze/test,

### Граница coordinator

Один main isolate приложения, одинаковая идентичность backing namespace у обёрток,
все обращения через InstallationService. HTTP не держит storage-очередь.
Неотменяемый write, начатый до отзыва, может временно записать старое значение;
новый владелец ждёт завершения и очистки именно этой неопубликованной записи.
Подтверждённые ранее credentials при dispose не удаляются. Reset сразу отзывает
прежние попытки и упорядочивает delete с очисткой старой SQLite-операции до допуска
новой. Ошибка storage блокирует пару до успешного явного reset.

Это **не атомарная транзакция secure storage + SQLite при OS-crash**, не platform CAS,
не гарантия fsync и не межпроцессная блокировка. Зависший storage не освобождает
очередь по таймауту. Прямые записи в обход сервиса и другие isolate/process не
покрыты; до успешного завершения reset удаление не обещается. Отмена HTTP не
отзывает созданную серверную установку и не возвращает регистрационную квоту.

## Ограничения и следующий шаг

- **iOS на Linux не собирался и не запускался.** Signing/Keychain/ATS/Local Network
  требуют отдельной проверки на macOS и устройствах. Нет подтверждённого теста
  OS-crash в момент COMMIT, переустановки/backup и физического удаления данных.
- SQLite не шифруется, токен хранится отдельно в secure storage. Android Auto Backup
  отключён; поведение ОС/MDM/backup и токена после переустановки не гарантируется.
- Плагин 10.3.4 сам пишет native-диагностику в logcat без публичного выключателя.
  Приложение не копирует исходные исключения/storage в UI/логи, native-runner
  не сохраняет и не выводит сырые диагностические данные плагина.
- Recovery требует подтверждённого retention и корректных часов. Вечная
  идемпотентность, recovery/rotation/revoke токена и серверная отмена не обещаются.
- demo_unverified сохраняется: актуальные цены магазина, наличие, география,
  КБЖУ каталога, реальная готовка и заявленное время не подтверждены этим E2E.
- Полноценное меню 3 дня × 3 приёма, стабильность генерации и недельный сценарий
  не оценены. Выбор исключений/нелюбимых продуктов, заметки и отметки купленного
  отложены. Медицинская полноценность и безопасность при аллергии не гарантируются.
- HTTPS-окружение закрытого пилота, production IDs/signing, внешняя abuse-защита,
  нагрузка и удалённый CI пока не подготовлены/не подтверждены.

**Следующий шаг, не выполненная работа:** оценить полноценное меню **3 дня × 3 приёма**,
затем подготовить **HTTPS-окружение закрытого пилота**. Новые платные вызовы требуют
отдельного согласования; автоматически их не выполнять. Остальные направления — ROADMAP.
